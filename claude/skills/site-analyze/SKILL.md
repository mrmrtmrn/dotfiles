# /site-analyze

指定された URL のウェブサイトを分析し、サイトの全体像を構造化されたレポートとして出力する。
分析結果は、学習計画の立案やコンテンツの理解など次のアクションにそのまま活用できる形にすること。

## 使い方

- `/site-analyze <URL>` - 指定 URL のサイトを分析してレポートを出力（デフォルト: 最大5ページ取得）
- `/site-analyze <URL> deep` - より多くのページを探索して詳細に分析する（最大15ページ取得）

## 前提

- `$ARGUMENTS` には分析対象の URL が含まれる（必須）
- URL が与えられていない場合は、ユーザーに URL の入力を求めて終了する
- `$ARGUMENTS` に `deep` が含まれる場合はディープモードで実行する

---

## 分析手順

### ステップ 1: トップページの取得と概要把握

`WebFetch` を使ってトップページを取得し、以下を把握する：

- サイトの名称・運営者
- サイトの目的・対象読者
- 主要なナビゲーション構造（メニュー、サイドバー等）
- サブページへのリンク一覧

**プロンプト例:**

```
以下の情報を抽出してください：
1. サイト名と運営者
2. サイトの目的・概要
3. 対象読者
4. グローバルナビゲーションのメニュー項目とそのURL
5. ページ内の主要なセクションとリンク先URL
```

### ステップ 2: サイト構造の探索

ステップ 1 で得たリンクのうち、サイトの構造理解に重要なページを `WebFetch` で追加取得する。

- **通常モード**: 最大 **5ページ** まで
- **ディープモード**（`deep` 指定時）: 最大 **15ページ** まで

**優先順位:**

1. サイトマップページ（`/sitemap`, `/table-of-contents` 等）
2. 目次・一覧ページ
3. カテゴリ・セクションのトップページ
4. ドキュメントの場合は Getting Started / Introduction

**注意:**

- 同一ドメイン内のページのみ対象とする
- 外部サイトへのリンクは構造分析では追わない
- 取得に失敗したページはスキップして続行する

### ステップ 3: コンテンツ分析

取得した全ページの情報を統合し、以下を分析する：

- コンテンツのカテゴリ分類
- 各カテゴリに含まれるトピックの一覧
- コンテンツの深さ（入門〜上級など）
- 更新頻度の手がかり（日付情報があれば）

### ステップ 4: レポート出力

以下のフォーマットでレポートを出力する：

```markdown
# サイト分析レポート: [サイト名]

> **URL**: [分析した URL]
> **分析日**: YYYY-MM-DD
> **モード**: 通常 / ディープ

## 1. サイト概要

| 項目 | 内容 |
|------|------|
| サイト名 | ... |
| 運営者 | ... |
| 目的 | ... |
| 対象読者 | ... |
| サイト種別 | ドキュメント / ブログ / チュートリアル / リファレンス / その他 |

## 2. サイト構造

サイトの階層構造を ASCII ツリー形式で表現する。

例:
├── Getting Started
│   ├── Installation
│   └── Quick Start
├── Guides
│   ├── Basic Usage
│   └── Advanced Topics
└── API Reference
    ├── Core API
    └── Plugins

## 3. コンテンツ概要

### [カテゴリ名 1]
- トピック A: 簡潔な説明
- トピック B: 簡潔な説明

### [カテゴリ名 2]
- ...

## 4. 特記事項

- コンテンツの網羅性や特筆すべき点
- 見つかった制限事項（認証が必要なページ、未完成のセクション等）
- 関連する外部リソースへのリンク（見つかった場合）
```

### ステップ 5: 次のアクションの提案

レポートの最後に、この分析結果を活用できる次のアクションを 2〜3 個提案する。

例:
- 「このサイトをベースに学習計画を立てましょうか？」
- 「特定のセクションを深掘りしますか？」
- 「関連する他のリソースも調べますか？」
