# /session-note

このセッションで学んだ**汎用的な技術知識**を抽出し、TILリポジトリの `docs/Tech/AI-Sessions/` に記録する。
プロジェクト固有の情報は除外し、他の場面でも再利用可能な形に汎化すること。

## 使い方

- `/session-note` - セッションから学びを抽出 → ファイル作成/更新 → コミット
- `/session-note push` - 上記に加えて main へプッシュ

## 定数

**重要**: 日付は必ず以下の `date` コマンドを実際にBashで実行して取得すること。セッションのシステムコンテキスト（currentDate等）はセッション開始時の日付であり、日をまたいだ場合に正しくないため使用禁止。

```bash
TIL_DIR=$HOME/repository/github.com/mrmrtmrn/TIL
YEAR=$(date +%Y)
MONTH=$(date +%m)
TODAY=$(date +%Y-%m-%d)
TARGET_DIR=$TIL_DIR/docs/Tech/AI-Sessions/$YEAR/$MONTH
TARGET_FILE=$TARGET_DIR/$TODAY.md
```

---

## 抽出モード（常に実行）

### ステップ 1: セッションを分析して汎用知識を抽出

会話全体を振り返り、以下の観点で汎用的な学びを抽出する：

- 新しく学んだ技術知識・概念
- 問題解決のアプローチ・パターン
- ツールやコマンドの使い方・Tips
- 設計やアーキテクチャの知見
- デバッグ手法や落とし穴・ハマりポイント
- ベストプラクティスやアンチパターン

**抽出ルール:**
- プロジェクト固有のコード・設定・ファイルパスは含めない
- 特定のリポジトリ名や固有名詞はジェネリックな表現に置き換える
- 「Goのエラーハンドリング」「Reactのstate管理」のように、技術トピックとして独立して意味を持つ形にする
- 学びがない場合は無理に抽出せず、「このセッションでは新たな汎用的な学びはありませんでした」と報告して終了する

### ステップ 2: ディレクトリとファイルの確認

```bash
mkdir -p $TARGET_DIR
```

`$TARGET_FILE` が存在するか確認する。

### ステップ 3: ファイルの作成または更新

#### ファイルが存在しない場合（新規作成）

以下のフォーマットで作成する：

```markdown
# AI Session Notes - YYYY-MM-DD

## [トピックのタイトル]

### 学んだこと

- 箇条書きで汎用的な学びを記載

### 詳細

必要に応じてコード例や詳しい説明を記載する。
不要であればこのセクションは省略可。

## [別のトピックのタイトル]

...

## 参考リンク

- [記事タイトル](URL) - セッション中に参照したブログ記事やドキュメント

## メタ情報

- **ツール**: Claude Code / Gemini CLI / Codex など使用したツール名
- **関連技術**: Go, React, Docker など関連する技術タグ
```

#### ファイルが既に存在する場合（更新）

既存のファイルを読み込み、新しい学びを**1つの文書として自然に統合**する。

- 既存のトピックと被る内容があれば、そのセクションに統合・サマリしてまとめる
- 新しいトピックがあれば、文書の流れに合う位置にセクションを追加する
- コマンド実行ごとの区切りは入れない。あくまで1日分の学びとして一体の文書にする
- メタ情報セクションも新しいツールや技術タグがあれば追記する
- セッション中に参照したブログ記事・公式ドキュメント・外部リソースのURLがあれば「参考リンク」セクションに追記する。該当がなければセクション自体を省略してよい

### ステップ 4: コミット

```bash
git -C $TIL_DIR add docs/Tech/AI-Sessions/
git -C $TIL_DIR commit -m "feat: $TODAY の AI セッションノートを追加

- トピック1のタイトル
- トピック2のタイトル
- ..."
```

コミットメッセージは複数行で記述する：
- 1行目: `feat: $TODAY の AI セッションノートを追加`（タイトル行）
- 空行
- 3行目以降: 今回追記・新規作成したトピックのタイトルを箇条書きで列挙する

### ステップ 5: 完了報告

追記・更新した学びのサマリを簡潔に表示する。

---

## プッシュモード（`push` 引数）

`$ARGUMENTS` に `push` が含まれる場合、抽出モード完了後に以下を実行する。

### ステップ 6: プッシュ

```bash
git -C $TIL_DIR push
```

### ステップ 7: 完了報告

プッシュした内容のサマリを表示する。
